# API Reference

Base URL: `http://localhost:8000` (dev) · same origin via nginx (prod).
Interactive docs: `GET /docs` (Swagger UI, auto-generated by FastAPI).

All responses carry an `X-Request-ID` header. Errors always use one shape:

```json
{ "success": false, "error": "<code>", "message": "<human-readable>", "request_id": "<uuid>" }
```

| `error` code | Status | When |
|---|---|---|
| `http_error` | 4xx | bad input caught by a handler (incl. 404s) |
| `validation_error` | 422 | body doesn't match the schema below |
| `payload_too_large` | 413 | body over 64 KB |
| `rate_limited` | 429 | over 200 req/min (30/min on `/api/chat`) per IP |
| `internal_error` | 500 | unhandled — logged with the request_id, never a stack trace |

## GET /health

Liveness + dependency status. Used by Docker healthchecks and monitoring.

```json
{
  "status": "ok", "environment": "production", "version": "1.0.0",
  "uptime_s": 4211, "postings": 30795, "vectors": 30795,
  "qdrant_status": "ok", "model_configured": "fanar/Fanar-C-2-27B",
  "models_available": 7, "sessions": {"active_sessions": 3}, "memory_mb": 1102.4
}
```

## GET /metrics

Prometheus text exposition. Public access blocked by nginx in production —
internal scraping only. Families documented in [OBSERVABILITY.md](OBSERVABILITY.md).

## GET /api/datasets

Dataset dumps for the sidebar selector.

```json
{ "dumps": [ { "_dump_id": "qatar_may_2026", "_country": "Qatar",
               "_timeline": "May 2026", "_dump_label": "Qatar May 2026",
               "_source": "Bayt", "count": 2376 } ],
  "timelines": ["May 2026", "Jun 2026"], "sources": ["Bayt", "LinkedIn"] }
```

## GET /api/models

LLM choices for the UI. `{ "models": [{"label", "value"}...], "default": "fanar/Fanar-C-2-27B" }`

## GET /api/dashboard

All chart data in one call. Responses are cached in-process for 10 minutes per
unique parameter combination (data only changes on restart).

Query parameters:

| Param | Default | Meaning |
|---|---|---|
| `dumps` | *(all)* | comma-separated `_dump_id`s |
| `country` / `timeline` | `All` | exact-match narrowing (dataset-selection axes) |
| `sector` / `employment_type` / `career_level` / `company` / `experience` / `salary_bucket` | `All` | exact-match narrowing — one param per `filter_registry.py` entry; a value here filters **every** chart, matching the same filter sent to `/api/chat` |
| `n_sectors`/`n_skills`/`n_titles`/`n_companies` | 15/20/20/15 | top-N sizes |

Returns `total`, `countries`, `timelines`, `kpi_mom`, `sectors`,
`career_levels`, `employment_types`, `salary` (coverage/distribution/by-sector),
`skills`, `experience`, `company_size`, `languages`, `locations`, `job_titles`,
`companies`, `country_comparison`, `trends` — or `{"error": "..."}"` when the
filter combination matches nothing.

## POST /api/session

Creates a chat session. → `{ "session_id": "<uuid>" }`. Sessions hold the last
20 messages, expire after 2 h idle, capped at 10k concurrent (LRU-evicted).

## DELETE /api/session/{session_id}

Clears a session's history. → `{ "ok": true }`

## POST /api/chat

Streaming chat over Server-Sent Events. Rate limit 30/min/IP.

Request (validation rules in brackets — violations → 422):

```json
{
  "question":   "How many Technology jobs in Qatar?",   // 1–2000 chars
  "session_id": "e3612dba-...",   // required; [A-Za-z0-9_-]{1,64}
  "model":      "fanar/Fanar-C-2-27B",   // optional; unknown values fall back to default
  "dump_ids":   ["qatar_may_2026"],       // ≤100 identifiers — scopes ALL retrieval layers
  "filters":    {"sector": "Technology"}  // ≤20 entries; keys must exist in the
                                          // filter registry — one of: sector,
                                          // employment_type, career_level, company,
                                          // experience, salary_bucket (unknown keys
                                          // ignored); values ≤200 chars
}
```

Response: `text/event-stream`.

```
data: {"type": "retrieval", "info": { ...decomposition, layers_used,
        sql_snippet, semantic_hits... }}     ← first event: transparency panel

data: {"type": "token", "token": "There"}    ← repeated
...
data: [DONE]
```

The `retrieval` event arrives before tokens so the UI can show *what was
searched* while the answer streams. `info.filters` echoes the effective merged
filter set (UI filters override question-inferred ones on conflict) — this is
the ground truth for "what scope did the answer actually use."

## CORS

Origins from `ALLOWED_ORIGINS` only. Methods `GET, POST, DELETE, OPTIONS`;
headers `Content-Type`; no credentials; `X-Request-ID` exposed to the browser.
